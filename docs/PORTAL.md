# Public knowledge portal / 公開ナレッジポータル

The static site is built from the canonical registry and published by
[pages.yml](../.github/workflows/pages.yml) on master pushes or manual dispatch.
No external CDN, analytics, paid API or backend. The planned public URL is
https://yohi.github.io/agent-compass/ (availability depends on Pages configuration).

## Initial setup

In GitHub repository Settings → Pages → Build and deployment, select **GitHub
Actions** as Source. Save if prompted. Then run **Publish knowledge portal**
on master. If an environment protection rule requires approval, the owner
must approve the deployment. Do not change repository permissions or create
a personal access token to bypass this step. A successful build/artifact
does not establish successful deployment or browser reachability.

## Local preview

```sh
python build_site.py --output _site
python -m http.server 8000 --directory _site
```

Open http://localhost:8000/. Build output directory must be new; choose a
different directory or explicitly remove your old generated preview first.
Use HTTPS or localhost for browser cryptographic digest verification.

## Features and boundaries

- Japanese/English navigation and curated recommendations; English scope and
  metadata remain in the original registry language. Search target, model,
  category, status and recommendation text. Empty results do not imply that
  a model is discouraged.
- Side-by-side target guidance; no performance ranking or automatic migration
  claim. Model compatibility is not inferred.
- Generator: all valid explicit profile combinations and both languages
  are pre-generated by the existing Python function, not a JS reimplementation.
  Fetch a same-origin bundle and verify SHA-256 before display. The three
  files are proposals only, copied or saved by the user.
- Auditor Lite: six lexical checks (duplicate, runtime setting, review,
  reread, approval, size), scoped registry references and line numbers.
  Unlike the full CLI auditor it does not check other-model mentions or literal
  coverage, and regex/Markdown handling is not identical. No input excerpts
  in the report; no storage, network request or upload by the audit handler.
  No semantic verdict, no automatic changes. Browser extensions and user
  sharing are outside the site's control. Use CLI for local full coverage.
- Source dates and local evaluation states are registry metadata, not live
  availability. Monitor/discovery issues, Actions and changelog are linked;
  the site does not embed live operational state or fetch it from GitHub.

Only allowlisted web assets, validated registry data and generated public
bundles are published. Deployment uses separate build and deploy jobs,
least-privilege token scopes and SHA-pinned official actions. No issue state,
private inputs or model transcripts are packaged. The site automatically
rebuilds on master changes; source-monitor changes remain pending until a
curator adopts them.
